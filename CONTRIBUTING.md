# Contributing to sts2-sim

Thanks for helping. Issues and pull requests may be written in English or Chinese.

## How this repository is maintained

sts2-sim is **exported one way from a private upstream repository**. Every release here is generated by an export script; nobody commits to this repository directly. This keeps the public tree free of material that must stay private, but it changes how contributions land:

1. You open a pull request here. It is reviewed here, in public.
2. If accepted, a maintainer applies your commits to the upstream repository, keeping you as author or as `Co-authored-by`.
3. The change appears here with the next export. Your pull request is then closed with a note such as "included in v0.111.0.1" rather than merged.

The directory layout is the same on both sides, so patches apply unchanged. Please do not be surprised when a pull request is closed instead of merged; that is the normal path.

## Reporting a fidelity difference

The most valuable contribution is a reproducible case where the simulator behaves differently from the game. A good report has:

- **Game version** (the simulator's baseline is shown in the README).
- **Seed, character and ascension level.**
- **Steps**: the choices made up to the point of difference (floor, room, cards played).
- **Expected** (what the game did) and **actual** (what the simulator did).
- Ideally, the relevant game code you compared against. Describe it or cite the type and method name; please **do not paste large blocks of decompiled game code** into issues or pull requests.

## Rules for code changes

The full rules, written so that AI coding assistants can follow them too, are in [AGENTS.md](AGENTS.md). In short:

- **Follow the game, not intuition.** Fixes must match the game's actual code. When the game has overloads or default parameters, port the exact call; do not rewrite it by meaning.
- **Do not add RNG draws, reorder RNG draws, or loosen a comparison** to make a result match. Find the first point where the simulator and the game diverge and fix that.
- **Intentional deviations** (places where the simulator knowingly differs from the game) must be stated in the pull request, with the game's behaviour, what the simulator does instead, and why.
- **No game files.** Never commit game assemblies, decompiled source files, assets or localization text. Every export is scanned for binaries and other such content before it is published.
- **Keep the two RNG modes separate.** `CloneExact`, `CloneReseeded` and the keyed mode are intentionally separate APIs; do not merge them behind a boolean flag.
- **Tests:** add a test only when it would fail for a specific, behaviour-breaking change. Prefer `[Theory]` with `[InlineData]` over several near-identical `[Fact]`s. A green test suite is not proof of fidelity; a test that asserts the simulator's own mistaken behaviour is worse than no test.

## Build and test

Requires the .NET 9 SDK. No game files are needed.

```sh
dotnet build Sts2Sim.sln -c Release
dotnet test Sts2Sim.sln -c Release
dotnet test Sts2Sim.sln -c Release --filter "FullyQualifiedName~<ClassName>"
```

## Labels

| Label | Meaning |
|---|---|
| `fidelity` | Behaviour differs from the game |
| `known-deviation` | Intentional difference from the game; not planned to change |
| `bug` | Crash or incorrect behaviour not tied to a specific game comparison |
| `needs-repro` | Missing seed or steps to reproduce |
| `game-version` | Drift caused by a new game version |
| `good first issue` | Suitable for a first contribution |
